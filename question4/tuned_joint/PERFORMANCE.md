两次诊断的完整396条命令均与 `outputs/structure_corrected/develop_histories/replacement/20295000.json.gz` 逐条相同，包含动作、位置、频道、反馈、费用与决策对象。完整动作时间均为7119.904492286173秒；该场13个源，即547.684960945秒／源。这是同场重复核验，不增加独立样本数。

| 运行 | 规划／运行墙钟 | 条件 |
|---|---:|---|
| 之前的结构开发记录 | 79.14秒 | 较早批次，无cProfile |
| 本次原策略剖析 | 172.22秒 | cProfile开启，同时有其他计算任务 |

## 最大热点

cProfile记录39468065次函数调用，总172.219秒。下表包含嵌套累计时间，各行不能相加。

| 调用 | 次数 | 累计秒数 | 含义 |
|---|---:|---:|---|
| `DirectionalCoverage._certify` | 8720 | 153.04 | 连续覆盖充分证书检查，占总剖析时间约88.9% |
| `certificate_details` | 8626 | 152.51 | 凸包、Delaunay及短边检查 |
| `forecast_plan` | 2264 | 117.84 | 候选停点能否删除未来支持点 |
| `measurement_value` | 6912 | 6.35 | 已知源条件测量价值 |
| `_unknown_values` | 7604 | 4.80 | 未知频道的方向残余价值 |
| `open_order` | 2634 | 0.32 | 共同开放路线排序与2-opt |

当前最值得处理的是重复几何认证。条件积分、最小包围圆和2-opt并非本次墙钟开销的主因。降低积分精度或削减候选会改变动作，不能当作“保持算法结果不变”的实现提速。

还有一个本机相关的明显开销：当前SciPy版本为1.18.1，凸包／Delaunay调用路径触发临时文件创建。剖析记录17308次 `tempfile.mkstemp`，累计50.23秒，其中 `nt.open` 自身49.49秒；17184次临时文件调用直接来自 `certificate_details`。几何构造的部分原生执行时间被记在该函数自身99.65秒中。这证明减少Qhull调用也能减少临时文件开销；没有证据将其具体归因于杀毒软件或某个磁盘设置。

## 临时缓存实验

只在独立Python进程内替换 `question4.free_joint.frozen_dynamic.coverage.certificate_details` 的函数引用，未修改任何仓库执行文件。原 `_certify` 的已记忆证书子集检查、证书记忆和真实无源认证逻辑全部保留。

缓存键为输入转换成float64并整理为 `(n, 2)` 后的**形状及按原顺序保存的完整字节**。没有四舍五入、网格量化、排序或集合化；不把未来测点写入真实观察。命中时返回结果的深复制，避免共享可变返回对象。

| 项目 | 实测值 |
|---|---:|
| 纯几何函数请求 | 8626 |
| 精确键命中 | 1748 |
| 命中率 | 20.26% |
| 真正调用几何函数 | 6878 |
| 未通过证书的首次计算 | 6678 |
| 通过证书的首次计算 | 200 |
| 未缓存几何累计墙钟 | 119.58秒 |
| 完整396条命令一致 | 是 |

这证明精确缓存能够避免20.26%的几何调用，并在这一训练场景上保持完整动作记录不变；尚未证明所有场景上的等价性或稳定加速比例。没有保存原始缓存键集合，因此不能在进程结束后离线计算进一步规范化能够增加多少命中；本轮没有为此追加实验。

## 后续实现优先级

1. **缓存纯几何结果，保留单调证书查询。** 当前 `_certify` 首先检查已有完整证书是否为输入点集的子集。以后即使旧Delaunay充分检查失败，也可能因新记忆的子集证书而成功，所以不能直接永久缓存整个 `_certify` 的失败返回。应保持这一检查在前，只缓存后面的纯 `certificate_details`，并限制内存使用。
2. **规范化纯几何键。** 原函数入口已执行 `np.unique(..., axis=0)`，因此可考虑以完全相同的unique结果、形状和字节为键，避免不同输入排列重复计算。不应自行改用近似坐标或不同几何规范化。此项尚未实施、尚未测量命中率。
3. **缓存一次决策中的 `forecast_plan`。** 成组扫描判定、替站候选生成和未来路线估计会重复请求同一条件补盲方案。键需要保留有序未来坐标、精确候选坐标、未知频道集合和虚拟测量频道集合；缓存边界还必须覆盖真实观察与已记忆证书的变化。最容易审计的做法是在每次完成参考方案更新之后建立仅供本次choose使用的缓存，不跨真实反馈保留旧结果。
4. **再处理次要重复。** `_unknown_values` 内部多次遍历频道观察记录，`_covered_at` 在本次剖析中调用105251次、累计4.28秒。若主几何瓶颈已经削减，可按实际观察版本缓存固定位置查重和残余统计。当前优先改积分或2-opt收益有限。

这些属于实现候选，不是已经合入的提速。任何后续合入都应保存新旧代码快照，在固定训练场景逐条比较完整动作，并在相同负载、同样是否开启剖析的条件下进行配对墙钟测量。不能用不同机器或不同时段的单次用时直接宣称加速。
